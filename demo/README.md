# Browser demo

Drop a USD file in, watch it convert to GLB in WebAssembly, and see it rendered by
**Babylon.js**.

```
USD bytes → [wasm: OpenUSD 26.08 + Adobe usdGltf plugin] → GLB bytes → Babylon.js
```

This is the source for the published demo. `npm run build` writes the repository's `docs/`
folder, which GitHub Pages serves.

## Run it

```powershell
npm install
npm start        # builds ../docs, then serves it at http://localhost:8080
```

`npm run serve` skips the rebuild. Any static server works — the shipped WebAssembly module
is single-threaded, so no COOP/COEP headers are needed.

> **Prerequisite:** `../js` must be built, since the demo consumes the npm package and its
> WebAssembly artifacts:
> ```powershell
> cd ../js; npm install; npm run build
> ```

## What to try

Three samples are built in:

| Sample | Exercises |
|---|---|
| **Cube + plane** | Authored `faceVarying` normals, `primvars:displayColor` |
| **Hierarchy** | Nested `Xform`s, `references`, translate/scale/rotate ops |
| **Materials** | Five `UsdPreviewSurface` shaders → `KHR_materials_*` |

For your own content:

- **`.usdz`** — self-contained, so a single file is enough.
- **Multi-file `.usd` scenes** — use **Whole folder**, or drag the folder onto the window.
  A root layer references its sublayers, payloads and textures by relative path, and those
  only resolve if the whole tree comes along. Picking just the root `.usd` is the usual
  cause of `Could not open asset …` errors.

The demo picks the shallowest USD file in the selection as the root layer, stages the rest
alongside it, and reports anything that stayed unresolved.

The panel shows conversion time, GLB size, and what Babylon ended up with (meshes,
vertices, triangles, materials, animations, skeletons).

## Asset resolution

Two kinds of reference behave differently:

- **Relative** (`@parts/robot.usda@`) — resolves against the referencing layer's
  directory. Works as soon as the folder is supplied.
- **Absolute from another machine** (`@/Users/someone/Desktop/robot.usda@`) — cannot
  resolve as written. DCC and Omniverse exports bake these in constantly.

For the second case the module ships a `WebResolver` that falls back to matching the
**file name** against the files you supplied, logging every redirect. So a scene whose
payloads point at someone else's Desktop still loads, provided you supply those files.

Anything genuinely absent is listed in the log as *"referenced file(s) were never
supplied"*.

Harmless noise you may also see:

- `Failed copying metadata: Cannot set value for unknown field 'hide_in_stage_window'` —
  Omniverse-specific metadata that core USD does not define. Ignorable.
- `Invalid mesh topology: offset N …` — an upstream Adobe bounds check that fires on
  well-formed quads; the geometry converts correctly regardless.

## Notes from building this

Two behaviours are worth knowing about, both visible in the demo:

- **Meshes with only `displayColor` get no glTF material.** Adobe's exporter writes a
  material when the prim has a `material:binding`; otherwise the colour travels as a
  `COLOR_0` attribute. Babylon's default material ignores vertex colours, so the demo
  attaches a small PBR material with `useVertexColors = true` to those meshes
  (`applyVertexColorMaterials` in `src/main.js`). Bound materials are left untouched.

- **Vertex counts grow.** The cube sample reports 40 vertices for what is an 8-vertex
  cube plus a 4-vertex plane. Authored `faceVarying` normals force the converter to
  expand every attribute to one vertex per triangle corner (36 + 4). This is the
  documented `forceVertexInterpolation` behaviour in the Adobe pipeline, not a bug —
  but it does mean converted meshes are larger than the USD source implies.

If a malformed file kills the module (OpenUSD treats some parse failures as fatal, which
aborts the wasm runtime), the demo detects it and transparently reloads.

## Layout

```
index.html          the page
assets/             sample .usda files, including a multi-file scene
screenshots/        images used by the READMEs
src/main.js         the app: converter + Babylon scene
webpack.config.mjs  bundles with webpack, stages wasm + assets into ../docs
scripts/serve.mjs   static server for ../docs
```

`../docs` is generated by `npm run build` and committed, because GitHub Pages publishes it.
